## 2. Divisão de responsabilidades por checkpoint

| Papel | CP4 — Idealização | CP5 — Protótipo | CP6 — Entrega final |
|---|---|---|---|
| **Product Owner** | Escopo, personas e pitch | Priorização do backlog e validação dos fluxos | Roteiro da apresentação final |
| **Design / UI** | Marca, paleta e telas conceituais | Telas aplicadas ao protótipo | Ajuste fino visual e ícone final |
| **Dev Front-end** | Setup do Expo e organização de pastas | Navegação e telas funcionais | Integração com a API TMDB e build do APK |
| **Dev Dados / Mock** | Modelo de dados do clube e da rodada | JSON mockado e camada de serviços | Persistência local e tratamento de erro |
| **QA / Documentação** | README e documentos de escopo, marca e pitch | Roteiro de testes e evidências de execução | Manual de uso e documentação final |

## 3. Organização do trabalho

- **Repositório:** um único repositório Git para os três checkpoints, com a
  documentação versionada junto do código em [`docs/`](.)
- **Commits:** mensagens em inglês, no formato `tipo: descrição`
  (`feat`, `fix`, `docs`, `chore`), com um commit por mudança lógica
- **Branch:** `main` como branch de entrega de cada checkpoint
- **Evidências:** prints e vídeos de cada entrega ficam em `docs/evidencias/`
